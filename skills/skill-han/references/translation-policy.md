# 翻译与说明规则

## 菜单名称

- 格式固定为 `中文功能名（原 skill 标识）`，例如 `PDF 处理（pdf）`。
- 中文部分优先使用用户一眼能懂的动作或产物，不使用生硬直译。
- 原标识原样保留，包括大小写、连字符和命名空间后的名称。
- 最多 40 个字符；不要添加 emoji。

## 简短用途

- 目标长度为 20–40 个中文字符，最多 64 个字符。
- 说明“能做什么 + 最典型场景”，例如“读取、合并、拆分和填写 PDF 表单”。
- 不写“这是一个用于……”之类的套话，不复述 skill 名称。
- 库名、命令、协议、格式、schema 字段和专有名词保留英文。
- 命令、路径、URL、代码、变量名和数值必须逐字保留。

## 常用术语

| 英文 | 默认译法 |
| --- | --- |
| skill | Skill |
| plugin | 插件 |
| workflow | 工作流 |
| review | 审查 |
| refactor | 重构 |
| debug | 调试 |
| deploy | 部署 |
| test | 测试 |
| citation | 引文 |
| manuscript | 稿件 |
| spreadsheet | 电子表格 |
| presentation | 演示文稿 |
| commit | 提交 |
| pull request | Pull Request |

同一概念在一个批次内保持一致；不要为了统一译名改写原文中的技术标识。

## ECC 迁移命令

`migrated-command-skills` 的 `/` 菜单标题直接读取 `SKILL.md` frontmatter。此类条目使用译文中的
中文功能名替换 `name`，使用简短用途替换 `description`。菜单显示名不保留冗长的
`source-command-` 前缀；原始目录和稳定 key 仍用于更新、备份与恢复。

## 中文使用说明

说明采用以下结构：

1. **一句话用途**：普通用户能理解的结果。
2. **什么时候用**：列出 2–4 个具体触发场景。
3. **什么时候别用**：仅在与相邻 Skill 容易混淆时说明。
4. **直接这样说**：给 1–3 条可复制的中文请求示例。
5. **需要准备**：文件、数据、权限、账号或上下文。
6. **会得到什么**：产物类型、保存行为和格式。
7. **注意事项**：破坏性操作、外部写入、授权、费用或联网风险。

只根据目标 `SKILL.md` 及其直接资源陈述能力，不补充未经证实的承诺。用户不需要阅读英文正文。
